# AALL — محرّك الدراسة الذاتي

> نظام يخطّط دراستك، يجدولها في تقويمك، يتابع إتقانك، ويكتب لك تقريرًا — **بلا أن تفتحه**.
> مبني على التكرار المتباعد (spaced repetition) وضغط الامتحانات، ويعمل بلا أي تبعية خارجية.

آخر تحديث آلي: انظر `data/state.json` → `meta.lastTickAt`.

---

## المشكلة التي يحلّها

الطالب لا يفشل لأنه لا يعرف «ماذا يدرس»، بل لأن ثلاثة أشياء تنهار مع الوقت:

1. **القرار اليومي**: كل صباح تعيد اختراع خطة اليوم، فتستهلك طاقتك الذهنية قبل أن تبدأ.
2. **النسيان**: تدرس موضوعًا اليوم ولا تعود إليه إلا قبل الامتحان بأسبوع، حين يكون قد ضاع.
3. **التتبّع**: لا تعرف فعليًا ما أتقنته وما لم تُتقنه، فتذاكر ما تحبّه وتتجنّب ما تخافه.

AALL يأخذ هذه الثلاثة عنك: يقرّر، يجدول، ويقيس. أنت تُنفّذ فقط.

## كيف يعمل — الحلقة الكاملة

```
        ┌──────────────────────────────────────────────┐
        │  نبضة (tick) كل 15 دقيقة — آمنة وقابلة للتكرار │
        └───────────────────┬──────────────────────────┘
                            ▼
   1. قراءة الحالة        data/state.json  (إتقان، فواصل، مواعيد)
   2. قراءة الوقت المتاح  config/study.json (ساعاتك) − الالتزامات
   3. الترتيب             خطر النسيان + فجوة الإتقان + ضغط الامتحان
   4. التوزيع             جلسات 38 د + استراحة 10 د، بلا مادتين متتاليتين
   5. صندوق صادر          تقويم · ملاحظات · مهام · بريد
   6. تسليم               ملفات محلية قياسية الآن، أو Webhook لاحقًا
```

كل خطوة مكتوبة في `src/engine/`، ومغطّاة باختبارات. لا يوجد «سحر» ولا ذكاء اصطناعي مخفي:
كل قرار له معادلة، وكل جلسة في الجدول تحمل **سببها** مكتوبًا بجانبها.

### كيف يُرتَّب الموضوع؟

```
الأولوية = (0.45 × خطر النسيان + 0.35 × فجوة الإتقان + 0.20 × الصعوبة) × ضغط الوقت
```

- **خطر النسيان**: منحنى نسيان أُسّي يعتمد على الزمن المنقضي من الفاصل الزمني.
- **فجوة الإتقان**: `1 − mastery` (الإتقان متوسط متحرك من جودة استرجاعك).
- **ضغط الوقت**: `1` عادةً، ويصعد حتى `2.8` كلما اقترب الامتحان، وينزل إلى `0.15` بعد انقضائه.

هذه الأوزان في `src/engine/srs.mjs` وهي أرقام صريحة، لا صناديق سوداء.

### كيف يُحدَّث الإتقان؟

بعد كل جلسة تسجّل جودتها (`تعثّر / صعب / جيد / سهل`)، يُعاد حساب:

- **الفاصل الزمني** بنسخة ملطّفة من SM-2 (سقف 60 يومًا، حتى لا «يختفي» الموضوع شهرين).
- **الإتقان** كم متوسط متحرك يراعي مدة الجلسة (45 دقيقة تُرسّخ أكثر من 10).
- **الموعد القادم** = اليوم + الفاصل الزمني.

التعثّر لا يعاقبك: يعيد الفاصل إلى يوم واحد ويسجّل `lapse`، ثم يعيد البناء.

## التشغيل

```bash
npm start        # اللوحة + المحرّك الذاتي على المنفذ 4173
npm test         # 42 اختبارًا (بلا تثبيت أي تبعية)
npm run tick     # نبضة واحدة الآن
npm run plan     # طباعة خطة اليوم في الطرفية
npm run report   # تقرير الأسبوع
npm run dispatch # تسليم الإجراءات المعلّقة
npm run doctor   # فحص الحالة والإعدادات
npm run review -- --topic math-deriv --quality 4 --minutes 45
```

لا يوجد `npm install` في أي خطوة: **صفر تبعيات**. Node 20+ فقط.

## لوحة التحكم

`http://localhost:4173` — عربية، من اليمين لليسار، تعمل على الهاتف:

- **حلقة تقدّم** تقارن ما أنجزته اليوم بالخطة.
- **جدول زمني** لكل جلسة مع سببها وخطر نسيانها.
- **نقاط الخطر** و**أقرب الامتحانات**.
- **شريط إتقان لكل موضوع** + أربعة أزرار لتسجيل جودة الجلسة.
- **إضافة موضوع/مادة** من الواجهة (تُكتب في `config/study.json`).
- **حالة التشغيل الذاتي**: آخر نبضة، الصندوق الصادر، الموفّرين.

كل تعديل في الواجهة يُحفظ في الإعدادات، ويدخل التخطيط في النبضة التالية.

## الأتمتة — ثلاثة مستويات، اختر واحدًا

### 1) الخادم (الافتراضي، يعمل الآن)
`npm start` يشغّل نبضة عند الإقلاع ثم كل 15 دقيقة. يكفي أن يبقى الجهاز/الحاوية يعمل.

### 2) cron على جهازك
```cron
*/30 * * * * cd /path/to/AALL && /usr/bin/node src/cli.mjs tick >/dev/null 2>&1
```

### 3) GitHub Actions (يعمل حتى وجهازك مغلق)
`.github/workflows/study-tick.yml` — يشتغل يوميًا، ينفّذ النبضة، **ويعيد حفظ ذاكرة النظام في Git**
(`data/state.json`, `data/plans/`, `data/log/`, `data/reports/`). المستودع نفسه هو قاعدة البيانات،
فلا تحتاج سيرفرًا ولا اشتراكًا. ملفات التسليم (`data/out/`) تُحفظ كـ artifact لا في Git.

## الربط بالأدوات الحقيقية

الآن التسليم **محلي**: ملفات `.ics` و`.eml` قياسية في `data/out/<اليوم>/` يمكن استيرادها بنقرة.
هذا مقصود: النظام لا يتعطّل إذا انقطعت خدمة، ولا يحتاج مفاتيح سرية ليعمل.

للانتقال إلى المزامنة الحقيقية (Google Calendar / Gmail / Notion / Linear) بدّل الموفّر:

```jsonc
"automation": {
  "providers": { "calendar": "webhook", "mail": "webhook", "notes": "webhook", "tasks": "webhook" },
  "webhook": { "url": "https://script.google.com/macros/s/XXXX/exec", "token": "سر-اختياري" }
}
```

يرسل المحرّك عندها `POST` بجسم `{ action }` لكل إجراء، مع ترويسة `x-aall-action`.
أبسط جسر هو Google Apps Script (Calendar + Gmail + Sheets).

**ما تم تنفيذه فعلًا في حسابك**:
- تقويم **«AALL · الدراسة»** (`automation.calendarId`) مع جلسات اليوم الأربع وتنبيه قبل 5 دقائق.
- رسالة موجز صباحية على `s.elghribi@edu.umi.ac.ma`.
- المواد الابتدائية: رياضيات، فيزياء، برمجة، إنجليزية — عدّلها لتطابق وحداتك الحقيقية.

> ملاحظة صريحة: Notion لم يُربط لأن مساحة العمل لا تحتوي أي صفحة مشتركة مع التكامل
> (صفحات الأعضاء وحدها لا تقبل محتوى). أنشئ صفحة واحدة وشاركها مع التكامل، وسيعمل الربط.

## ما لا يفعله (حدود صريحة)

- **لا يقرأ محتوى دروسك.** لا يلخّص PDF ولا يحلّ تمارين. مسؤوليته إدارة الوقت والمراجعة.
- **لا يقيس جودة استرجاعك بنفسه.** يعتمد على تقييمك بأربعة أزرار — وهذا أصدق من تخمين آلي.
- **لا يعرف درجاتك.** لا يستنتج «إتقانًا» من علامة امتحان، بل من ممارستك.
- **لا يمنعك من التخطيط اليدوي.** لكن كل تعديل يدوي للجدول يُلغي ميزة التداخل والضغط.
- **النبضة تحتاج عملية حيّة.** على GitHub Actions تعمل مرة يوميًا، لا كل 15 دقيقة.

## المبادئ

1. **صفر تبعيات** — النظام يجب أن يعمل بعد 5 سنوات بلا `npm install` مكسور.
2. **كل قرار قابل للتفسير** — كل جلسة تحمل سببها؛ كل رقم له معادلة.
3. **الفشل لا يُفقد شيئًا** — الكتابة ذرّية، والإجراء الفاشل يبقى في الصندوق، والملف التالف يُعزل.
4. **الاختبار قبل الادّعاء** — 42 اختبارًا تغطي الحدود، المناطق الزمنية، والتكرار الآمن.
