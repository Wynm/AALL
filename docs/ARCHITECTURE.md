# المعمارية

## الفكرة المركزية: قرار ≠ تسليم

أغلب أدوات «الأتمتة» تفشل لأنها تخلط بين شيئين:

1. **القرار**: ماذا يجب أن يحدث اليوم؟ (خوارزمية، حتمية، قابلة للاختبار)
2. **التسليم**: كيف يصل ذلك إلى تقويمك وبريدك؟ (شبكة، مفاتيح، أعطال)

هنا الفصل صارم. المحرّك يقرّر ويكتب **إجراءات** في صندوق صادر، وطبقة الموفّرين تُسلّمها.
النتيجة: انقطاع Google لا يُفقد الخطة، وتغيير المزوّد لا يمسّ الخوارزمية.

```
config ─┐
state  ─┼─► planner ─► plan.json ─┬─► outbox ─► providers ─► .ics / .eml / .md / webhook
log    ─┘                          └─► dashboard (server)
```

## نموذج البيانات

### `config/study.json` — النية
ساعات التوفر، المواد، المواضيع، الصعوبة، تواريخ الامتحانات، تفضيلات الجدولة.
يُتحقق منه في `config.mjs`: قيمة غير صالحة تُصحّح وتُبلّغ، لا تُسقط النظام.

### `data/state.json` — الذاكرة
```jsonc
{
  "topics": {
    "math-deriv": {
      "mastery": 0.384,        // 0..1
      "ease": 2.4,             // معامل SM-2 (1.3..2.9)
      "intervalDays": 1,
      "reps": 1, "lapses": 0, "streak": 1,
      "minutes": 45,
      "dueDate": "2026-11-20",
      "lastReviewedDay": "2026-11-19",
      "history": [{ "date": "2026-11-19", "quality": 4, "minutes": 45 }]
    }
  },
  "meta": {
    "planCreatedFor": "2026-11-19",   // علامة منع التكرار
    "briefSentFor": "2026-11-19",
    "reportSentFor": "2026-W47",
    "streakDays": 1,
    "totalMinutes": 45
  }
}
```

### `data/plans/<YYYY-MM-DD>.json` — القرار
خطة كاملة + مبررات + ملاحظات. تُكتب مرة واحدة في اليوم؛ لا تتغير تحت يدك أثناء التنفيذ.
هذا قرار تصميمي مهم: خطة تتغيّر كل 15 دقيقة تُنتج ارتباكًا لا مرونة.

### `data/log/<YYYY-MM-DD>.jsonl` — الأثر
سجل إضافي فقط (append-only): نبضات، جلسات، إجراءات. لا يُعدّل ولا يُعاد كتابته.
هو المصدر لبناء التقارير، ويمكن استرجاع أي رقم منه.

## تدفّق النبضة

1. **قراءة** الحالة، وإنشاء حالة لكل موضوع جديد.
2. **خطة اليوم**: تُبنى إن غابت أو إن تغيّر اليوم (`meta.planCreatedFor`).
3. **إجراءات**: تقويم + ملاحظات + مهام — تُوضع في الصندوق مرة واحدة.
4. **موجز**: يُرسل بعد `dailyBriefHour` مرة واحدة (`meta.briefSentFor`).
5. **تقرير أسبوعي**: يوم `weeklyReportDay` مرة واحدة لكل أسبوع (`meta.reportSentFor`).
6. **تسليم**: تلقائي إذا `autoDispatch`، وإلا يدويًا أو من cron.
7. **حفظ**: `lastTickAt` + سطر في السجل.

كل العلامات في `meta` هي ما يجعل النبضة **متكرّرة بلا آثار جانبية**.
هذا هو الفرق بين «سكربت» و«نظام».

## لماذا ملفات بدل قاعدة بيانات؟

- صفر تبعيات، صفر ترحيلات، صفر نسخ احتياطي معقّد.
- `git diff` يوضّح كل تغيير في الذاكرة — مفيد جدًا عند التشخيص.
- يُنسخ إلى أي جهاز أو حاوية بلا إعداد.
- الكتابة ذرّية (`tmp` + `rename`) تحمي من التلف عند الانقطاع.
- الملاحظة الوحيدة: لا تصلح لآلاف المستخدمين المتزامنين — وهذا ليس هدف المشروع.

## المناطق الزمنية

كل الحسابات الداخلية على تواريخ `YYYY-MM-DD` بلا ساعات، والمنطقة تُستخدم فقط عند:
- تحديد «اليوم» و«الساعة» الحالية (`todayIn`, `hourIn`)،
- وتوليد `.ics` (`zonelessToUtc`).

هذا يلغي أكثر مصدر للأخطاء: حساب الفروق عبر تغيير الساعة الصيفية. الاختبارات تغطي
الدار البيضاء (+1 ثابت)، نيويورك (توقيت صيفي)، ولندن (BST).

## الأداء

الخطة اليومية: O(n log n) على عدد المواضيع (n صغير: عشرات). توليد ملف `.ics`
لعشرات الأحداث يستغرق أجزاء من الثانية. لا حاجة إلى تخزين مؤقت.
